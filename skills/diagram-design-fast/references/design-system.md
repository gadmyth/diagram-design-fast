# 视觉规范(与 diagram-design 上游兼容)

脚本生成的图必须满足这些规则;`check.mjs` 会逐条校验,不需要靠肉眼判断。

## 设计系统

- 一个强调色,只给 1–2 个焦点节点(其余用 ink / muted / paper-2)
- 1px 发丝边框,**零阴影**,圆角 ≤ 10px
- 三种字体角色:标题衬线(Instrument Serif)、节点名无衬线(Geist)、技术副标签等宽(Geist Mono)
- 密度目标 4/10:5 个节点通常够,8 个偏多,12 个必须拆
- 视觉密度高的时候**删节点**,不要塞更多

### 色板来源

默认色板**直接采用上游 diagram-design 的现行默认 skin**(jet-black / white-smoke /
burnt-tangerine),令牌名也沿用它的语义角色命名(`paper` / `ink` / `muted` / `soft` /
`paper-2` / `accent` / `link` / `rule`)。这样两个 skill 产出的图并排看是同一套视觉语言。

| 角色 | 用途 | 浅色 | 深色 |
|---|---|---|---|
| `paper` | 页面底色、**默认节点填充** | `#f5f5f5` | `#2d3142` |
| `paper-2` | 容器底、次级填充 | `#ececec` | `#393e53` |
| `ink` | 正文、描边 | `#2d3142` | `#f5f5f5` |
| `muted` | 次级文字、默认箭头 | `#4f5d75` | `#bfc0c0` |
| `soft` | 副标签、分区标签 | `#5a6580` | `#949eb2` |
| `accent` | 焦点节点(全图 ≤ 2) | `#bf4520` | `#f08a59` |
| `accent-fg` | 强调色上的文字 | `#ffffff` | `#111111` |
| `link` | HTTP/API 连线 | `#2e5aa8` | `#739fdf` |
| `rule` | 发丝分隔线 | `rgba(45,49,66,.12)` | `rgba(245,245,245,.12)` |

对比度契约:所有文字角色在各自 paper 上 ≥ 4.5:1(accent 作为文字时也是 4.5:1),
线条/箭头/边框 ≥ 3:1。`accent-fg` 按 skin 分别取白/黑,保证强调色上的文字始终可读。

> 上游改版时如果换了默认色板,这里要跟着改 `scripts/lib.mjs` 的 `SKINS`。
> 换色不影响布局——颜色是令牌,不是坐标。

## 4px 网格

节点原点和尺寸、间距、padding 全部整除 4。允许偏离的:字号、圆角、
数据推导出来的位置(端口坐标、标签位置)、描边宽度、透明度。

## 六条连接线规则

1. **只走直角**。不同轴的两个节点之间用圆角肘弯(`r=8`),禁止斜线;
   共用 x 或 y 时才用直线段
2. **标签必须遮罩 + 留缝**。遮罩矩形不透明,离描边留 6–10px 的可见间隙,
   标签永远不压在线上
3. **连线不许重叠**。必须交叉时给次要的那条加"桥"(hop)弧;天然会重叠就拉开 ≥12px
4. **共享边要散开端口**。同一节点同一条边上的 N 条连线,端口按 `L*k/(N+1)` 分布,
   相邻端口间距 ≥12px
5. **不许从非端点节点背后穿过**。默认绕开;实在绕不开就用虚线 + 标签放在可见端
6. **标签遮罩不许压到后画的节点**。遮罩必须落在空白画布上

## 复杂度预算

| 限制 | 数值 |
|---|---|
| 节点 | ≤ 9 |
| 连线 | ≤ 12 |
| 强调色元素 | ≤ 2 |
| 分区(zone) | ≤ 3 |
| 时序图参与者 | ≤ 5 |
| 时序图消息 | ≤ 12 |

超了就拆成"总览 + 细节"多张图,共享同一个 spec 目录。

## 无障碍契约

- `<svg role="img" aria-labelledby="<slug>-title <slug>-desc">`
- `<title>` 必须是 `<svg>` 的第一个子元素(在 `<defs>` 之前)
- id 必须带 slug 前缀,不能是裸 `title` / `desc`(多图内联时 id 会撞)
- `<title>` = 主体短名;`<desc>` = 一句话说明内容,不是描述几何

## 单文件安全

- 不许有 `<script>`
- 不许有 `<img>` 或外链图片
- 外链只允许 Google Fonts 样式表(默认用系统字体,零网络请求)

## 图例

- 横向排在图**下方**,不在图区内
- 每行一条分隔线 + `LEGEND` 标签,条目用实线/虚线色块或小方框示意
- 画布高度要给图例留出空间(自动按条目数折行)

## 与上游 diagram-design 的关系

上游(cathrynlavery/diagram-design)定义了同样的视觉语言,但只提供"从零生成"的路径:
没有修订流程,坐标全靠模型手算,所以改图会重新读源码、重算全部坐标。

这个 skill 复用上游的视觉规范(网格、连接线规则、预算、无障碍契约),
把几何计算换成脚本,并补上 spec 化的修订流程。两者产物可以混用:
上游产出的 HTML 可以直接读;本 skill 产出的 HTML 也符合上游的校验口径。

若上游已安装(`/diagram-design:*` 命令),两者可以并存:
上游管"好看的最终稿",本 skill 管"从源码出发、可反复修订的图"。
